# RTO Shield AI - Model 1: Experiments

> Generated by `src/11_experiments.py`. Read-only: the final model, calibrator, thresholds and metrics were not changed. Adoption rule: validation ROC-AUC gain > 0.01 and passing leakage tests. `Order Status` is never a model feature (verified: no forbidden/Order-Status columns among the 252 encoded features).

## Conclusions in plain English

**Bottom line: nothing clears the adoption bar, so the final model stays as it is.** A variant must beat the final model on validation ROC-AUC by more than 0.01 and pass the leakage tests (passed: 6 passed in 16.48s). `Late_delivery_risk` remains the primary reported target.

1. **Segment specialists.** Standard Class: global 0.529 vs specialist 0.528 (paired delta -0.0013, 95% CI -0.0113 to +0.0075; validation gain -0.0058). Second Class: global 0.567 vs specialist 0.562 (delta -0.0043, CI -0.0207 to +0.0133; validation gain -0.0105). Neither specialist beats the global model by a meaningful margin: the missing signal is in the data, not in the model structure. **Not worth adopting.**

2. **Alternative target (delivery_failure = late OR cancelled OR suspected fraud).** The alternative-target model reaches test ROC-AUC 0.780 (95% CI 0.771 to 0.789) on its own target, vs 0.753 for the final model scored on that same target. But the gain is not better delivery-risk skill: scored on `Late_delivery_risk` it is worse (0.746 vs 0.772), and on the cancel/fraud part alone it is weak (AUC 0.660, PR-AUC 0.074 vs 0.043 prevalence). What drives it is the same as for the late model: shipping mode and scheduled days (shipping mode 59%); Payment type's share falls from 13% (late model) to 8%, because once cancelled / fraud orders count as failures the TRANSFER 'protective' artefact largely disappears. **Keep it as an evaluation-only secondary target; do not adopt it.**

3. **Cleaned task (cancelled / fraud orders excluded, 4.3% of test orders).** Overall the variant scores 0.774 vs 0.775 for the final model on the cleaned population (validation gain +0.0029, below the 0.01 bar; paired test delta -0.0009, CI -0.0067 to +0.0053). Payment type's share of attribution falls from 13% to 0.1%: the TRANSFER effect was the artefact. **The important finding is about the existing model, not the variant:** on cleaned orders the final model's within-mode AUC is 0.504 for Standard Class and 0.500 for Second Class (vs 0.529 and 0.567 on all orders). Inside those two modes the model has essentially no ranking ability once the artefact is removed; the modest 'limited' signal reported earlier was partly the cancel/fraud labelling. First Class has no variation at all (every cleaned order is late). At checkout the order status is unknown, so the production model cannot drop these orders. **Do not replace the model; do adopt the cleaned population as a reporting view.**

**What adopting would change in the report.** Nothing about the model or its thresholds. The report would (a) add the cleaned-population ROC-AUC next to the all-orders figure, (b) change the Standard / Second Class wording from 'limited signal' to 'no demonstrable ranking signal on cleaned orders', (c) state that Payment type is excluded from any causal reading, and (d) show the cancel/fraud AUC as a separate secondary result, never mixed into the late-delivery metrics.
